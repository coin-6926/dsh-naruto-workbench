> **你可以直接照这份文件工作。** 目标：把《火影忍者》手游战力数据里「中/低/未证实」的项往上推。
> 生成日期：2026-10-18　|　数据层：`lib/power-data.js`　|　审计工具：`node tools/audit-confidence.mjs`

---

## 0. 这个项目是什么

一个**战力工作台**（DSH 插件 + 单文件 HTML + Node CLI 三形态）。
核心价值**不是**功能多，而是 **每个数字都标明来源和置信度，绝不编数字**。

**所以你的评分标准不是"搜到多少"，而是"有没有给出可追溯、可复算的证据"。**

## 1. 🚨 硬约束（违反等于白做）

### 1.1 绝不编数字或 URL

**识别特征（比域名更可靠，因为农场会换名）：**
- 域名 = `拼音/英文词 + 3位数字 + .cn/.com`
- 路径 = `/<4字母>zx01/`、`/<4字母>zx06/`、`/gamezx01/`、`/newszx06/`
- 文风：大段"1、2、3"编号攻略、无截图、无实测过程、数字不给单位
- 出现「小编」「以上就是关于…的全部内容」这类尾巴

**判定规则：如果三个"独立来源"都落在这类域上，那就是 1 个来源，不是 3 个。**
本项目已有先例：#5 暴击倍率「3 源一致」实为 3 个农场，已拒绝采纳。

### 1.3 口径陷阱（本项目在这上面栽过 4 次）

| 陷阱 | 表现 | 正确做法 |
|---|---|---|
| **总数 vs 默认值** | 「36 孔」是总位、「30 孔」是默认已开；「9 孔」是总孔、「6 孔」是默认开放 | 拿到数字先问：**这是总数还是默认/已开** |
| **达标线 vs 通关门槛** | 160 级达标 2000 万，但 160 团本实际要 3000~4600 万 | 明确写清是哪个 |
| **分组边界 vs 解锁节点** | 消耗分组是 0-4/5-9/10-14/15-19，但天赋解锁在 **5/10/15/20** | 两者差 1，别看混 |
| **属性系数 vs 百分比换算** | 1 点暴击属性 = 6 战力；但洗练 1% 暴击率 = 10 战力 | 两个不同维度，不能互相"修正" |

### 1.4 🚨 跨游戏污染
- `huoyin.qq.com` = **《火影忍者OL》端游**（回合制），**不是**本作手游
- 手游官网只有 **`hyrz.qq.com`**
- 看到「出手位 / 先攻 / 控制 / 忍术 / 抗性 / 五行查克拉 / 查克拉传递」→ 立刻判为 OL 资料，弃用

## 4. 输出格式（请严格遵守）

对每一项，按这个结构写：

```
### [编号] 项目名
- 结论：<数值或"未找到">
- 置信度建议：unverified / low / medium / high
- 来源：<标题>　<URL>　<日期>
- 原文引用：「……」（必须是页面上真实存在的句子，不要改写）
- 为什么可信 / 为什么不可信：<一两句话>
- 复算过程：<如果这个数字能验算，把算式写出来>
```

**如果没找到，也要写：**
```
### [编号] 项目名
- 结论：未找到
- 已尝试：<用了哪些 query / 看了哪些站>
- 判断：<是"网上确实没有"还是"被墙/打不开">—— 这两者区别很大
```

## 5. 三条加分项（比搜到新数字更值钱）

1. **发现我的错误**：如果你发现数据层某个结论是错的（口径搞错、算式算错、来源配错），直接指出并给证据。本项目已有 4 次被外部纠正后改数，都记在 `docs/DATA-SOURCES.md`。
2. **给出可复算的算式**：一个能被复算验证的数字，价值 > 十个"据说是 X"。
3. **确认"真的没有"**：把"我尝试了 A/B/C 路径都打不开"写清楚，能防止后来者重复劳动。

## 7. 验收标准

你的产出会被这样检查：

1. 每个数字能否追溯到具体 URL 且能打开
2. 原文引用是否真实存在于页面
3. 可验算的数字，算式是否成立
4. 是否踩了农场黑名单
5. 是否犯了第 1.3 节的四种口径错误

**做对 3 项 = 合格；做对 5 项 = 优秀；编了数字 = 归零。**
