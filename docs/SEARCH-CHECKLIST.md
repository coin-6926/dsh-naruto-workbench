## 0. 检索前必读：三条硬规则

### 规则 1：先用官方通道，不要一上来就搜网页

```bash
# 读单篇官方公告
node tools/fetch-official.mjs --aid <id>
# 全栏目批量检索（找某系统上线公告用）
node tools/search-official.mjs --tags all --kw 关键词1,关键词2
# 列公告 / 搜标题
node tools/fetch-official.mjs --list --tag 18807
node tools/fetch-official.mjs --search 关键词 --pages 3
```

栏目 tagId：`18807=公告` `18812=新闻` `18808=攻略` `18813=活动`
**接口覆盖范围**：公告 -> 2021-02 起；新闻/攻略 -> 2016-08 起；每栏目上限 600 条。
2016 年的**公告**类文章超出窗口，`/webplat/` 老页面无列表页、id 不可枚举 -> 不可检索。

### 规则 2：来源分级（不满足就是不合格来源）

| 级别 | 判定 | 能否当独立来源 |
|---|---|---|
| A | `hyrz.qq.com` 官方公告（经 fetch-official 读到正文） | ✅ 最高 |
| B | 官方公告的**同日完整转载**（含原话级表述） | ✅ 次高 |
| C | 知名站点全文攻略（17173 / 小米 / 游民星空 / 九游） | ⚠️ 单源只能给 medium |
| D | 贴吧 / TapTap / 抖音 / B站（含实测截图） | ⚠️ 需旁证才给 medium |
| ❌ | 见下方黑名单与三类伪装 | ❌ 只能当"候选范围" |

## 三、🎯 实测捷径（比搜索更可靠，优先做）

搜索只能得到"别人说的"，下面这些**你自己做一次就能钉死**：

| 测什么 | 具体操作 | 一次能钉死 |
|---|---|---|
| 属性攻防系数 | 记下面板 -> **只换一件单属性不同的忍具** -> 看战力跳变 -> 相除 | 属攻 6 + 属防 10 + 顺手验防御 11.6 |
| 忍玉战力率 | 升 1 级神器，**只加忍玉不加轮回石** -> 记战力增量 | 忍玉率（把"不可唯一确定"变确定） |
| 防御系数 | 换一件**只改防御**的件 -> 反查面板 | 11.6 / 11.7 / 12 三选一 |
| 勾玉孔数 | 数自己开了几个槽（装备端 + 通灵端） | 总孔数（三方互斥在此终结） |
| 铜币日收益 | 记录一整天所有来源逐项加总 | 30~36 万是否成立 |
| 修罗天赋节点 | 升到下一个 60 级节点，记属性增量 | 验证 2320/660/200 -> 6950 |

## 四、检索时最该防的两个陷阱

### 陷阱 1：多站转载伪装成多来源

判据：**数字连单位写法/标点都一字不差** = 同源。
实例：2016 年一份魔方网稿件被 8+ 站逐字转载（连"暴击3600 生命10100 防御900"举例都一样）；
csdn 与 233乐园的云迹腰带四个数字**完全相同** -> 实际独立来源 = 1。

### 陷阱 2：结论正确但**数字**来自不可靠源

实例：「全通灵 +4 优先」这个**策略**有 2 源支持（可信），但同句的「+19008 战力」来自农场且文内自相矛盾。
-> **策略可用、数字撤下**。检索时要把这两者分开判断。

## 五、检索结果怎么回写

找到数据后，改 `lib/power-data.js` 对应字段，并**必须**同时更新：

1. `confidence` —— high / medium / low / unverified
2. `sourceIds` —— 加到 `SOURCES` 里并填 url / kind / retrievedAt / **verified**（是否真打开过）
3. 若与旧值冲突 → 写进 `dataConflicts2026`，**不要静默覆盖**
4. 若确认"搜不到" → 写进 `officialAudit.cases` 的 `implication`，注明"别再找"

改完跑：

```bash
npm run build:portable    # 重新打包 dist（否则单文件 HTML 是旧的）
npm run test:all          # 三套 323 项，必须失败 0
```
